# Patch 24 — Durable leases, write verification, reconciliation and encrypted snapshot

- Apply `0024_reliability.sql` with `node --env-file=.env.local scripts/apply-feature-migrations.mjs --apply` **before restarting the server**. It creates an atomic Neon write lease and write-receipt table; the lock is released after each write and expires in 90 seconds after a crash. **Not an atomic transaction with Google Sheets.** If a Sheets call exceeds the lease lifetime, an overlapping write is still possible. Keep a single Railway instance until load-tested; prevent manual direct editing during writes.
- Every department write now reads the row back and verifies the exact input cells; it retains a pending operation when verification fails. Receipt hashes contain no old/new clinical note contents.
- `/admin/reconcile` lists unresolved writes. A Super Admin must inspect the sheet and document a finding before marking an operation applied or not applied. This never retries a write.
- `scripts/encrypted-backup.mjs` exports a password-protected AES-256-GCM **data-only** snapshot of app tables and Sheets formula/value arrays; keep backups outside the repository, store passphrase separately and test `--verify`. Example PowerShell: `$env:KPI_BACKUP_PASSPHRASE = Read-Host 'Backup passphrase'` then `node --env-file=.env.local scripts/encrypted-backup.mjs --export --file=C:\\secure-backups\\dawson-2026-11-23.kpi`; verify with `--verify`. Remove `KPI_BACKUP_PASSPHRASE` from the shell when finished. Never upload the encrypted backup to a public repository.
- The backup is **not a complete disaster-recovery solution**: it omits Google Drive formats, protections, revisions, charts and Postgres permissions/extensions. Configure and test full Google Drive copy/export and Neon point-in-time recovery in the relevant service dashboards. Restore requires a separately reviewed procedure; no destructive auto-restore is provided.
- Never store direct patient names or full clinical note contents in audit, email, or target rationales. Test backup and restore on a separate development environment before enabling production.
